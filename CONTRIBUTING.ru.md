# Участие в Agent Kit

[English](CONTRIBUTING.md)

## Локальная разработка

Используйте Node.js 22.19 или новее. Обязательных npm-зависимостей и этапа сборки нет.

```sh
npm run check
npm test
```

В ходе работы запускайте целевые тесты, перед pull request — обе команды. Тесты используют встроенный runner Node и временные фикстуры. Отделяйте smoke-проверки клиентов и провайдеров от офлайн-проверок; явно указывайте пропуски и недоступные клиенты.

## Подготовка изменений к ревью

Посвящайте pull request одной проблеме. Опишите условие возникновения, итоговое поведение и проверку. При необходимости свяжите issue. Для CLI приложите примеры терминала, для визуальных изменений — снимки экрана. При изменении поведения обновляйте обе языковые версии затронутых документов и журнал изменений.

Используйте короткие повелительные заголовки коммитов, например `Preserve project rules during adapter updates`.

## Инварианты проекта

- Сохраняйте совместимость команд Pi, ресурсов пакета и опционального расширения.
- Сохраняйте офлайн-настройку, настройки проекта, посторонние файлы и обратимость обновлений.
- Описывайте нативные hooks отдельно от инструкций навыков.
- Делайте постоянные инструкции короткими; читайте тематические справки по необходимости.
- Проверяйте изменённое поведение, включая ошибки и конфликты отката, где применимо.
- Не добавляйте зависимости для задач, решаемых поддерживаемым Node напрямую.

Следуйте структуре и стилю из [AGENTS.ru.md](AGENTS.ru.md). Новым интеграциям нужны первичные источники контрактов ресурсов и тесты создаваемых файлов.

## Двуязычная документация

У каждого Markdown-документа есть английская и русская версии в `docs/languages.json`. Runtime-переводы находятся в `locales/ru/`, поэтому клиент обнаруживает только выбранный язык. Сохраняйте имена навыков, флаги, ключи метаданных и примеры кода. Обновляйте обе версии вместе, проверяйте смысл и ссылки, затем выполняйте `npm run docs:write` и `npm run docs:check`. Хеши выявляют изменения файлов после ревью, а не качество перевода. Добавляйте новые пары в каталог; проверка отклоняет Markdown без пары. Сторонние навыки из проверенного коммита сохраняют исходный язык и лицензию; комплект не переписывает чужое содержимое.

## Подготовка выпуска

Обновите версии в `package.json` и `versions.json`, журнал `CHANGELOG.md` и его перевод, выполните проверки и пересоздайте инвентарь через `npm run integrity:write`. Проверьте его командой `npm run integrity:check`. Соберите архив через `npm pack --ignore-scripts`; репозиторий не публикуется в npm автоматически.

Сообщайте о проблемах безопасности по процедуре [SECURITY.ru.md](SECURITY.ru.md), а не через публичный issue с credentials или приватным кодом.
