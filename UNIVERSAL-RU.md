# Универсальный Agent Kit

[English](UNIVERSAL.md)

## Что устанавливается

Agent Kit v2.3 — переносимое ядро навыков и Node.js-инструментов с адаптерами Pi, Codex, Claude Code и OpenCode. Команда `setup` создаёт проектную оснастку; это не установка самих клиентов или провайдеров.

| Возможность | Pi | Codex | Claude Code | OpenCode |
| --- | --- | --- | --- | --- |
| Проектные инструкции | AGENTS.md / активный AGENTS.override.md | AGENTS.md / активный override | CLAUDE.md | AGENTS.md |
| Навыки по требованию | .agents/skills | .agents/skills | .claude/skills | .agents/skills |
| Первый запрос | /efficient-task | $efficient-task | /efficient-task | /efficient-task |
| Контекстные пакеты, компактные логи, handoff | Да | Да | Да | Да |
| Нативные prompts/commands | Все 7 прежних Pi prompts | Через навыки | Через навыки | 7 команд |
| Нативный read guard и отдельный model worker | Опциональный context-tools | Не установлен | Не установлен | Не установлен |
| Глобальные настройки и профили Pi | Сохранён старый CLI | Не меняются | Не меняются | Не меняются |

Поддержка файловых контрактов проверяется автоматически. Только Pi имеет реализованный нативный guard/worker; skills у других клиентов не перехватывают вызовы инструментов. Живая совместимость каждого клиента проверяется отдельно от офлайн-тестов.

## Новый или существующий проект

Из каталога комплекта:

```sh
node scripts/agent-kit.mjs setup ../my-project --agents all --language ru --dry-run
node scripts/agent-kit.mjs setup ../my-project --agents all --language ru
node scripts/agent-kit.mjs doctor --target ../my-project
```

Используйте `--agents pi,codex`, если нужны только эти клиенты. Без аргумента в новой установке выбран Pi; повторный запуск использует ранее выбранных агентов. Явный список добавляет адаптеры к существующим, не удаляет остальные. `--preset deep` добавляет шесть навыков; обратного автоматического удаления при `lean` нет.

`npm run wizard` спрашивает язык, проект, агентов и опциональные Pi-инструменты, показывает полный план и применяет его после ответа `y` или `да`. В CI используйте `setup` с аргументами; мастер без терминала завершается с инструкцией, не зависает. Для Windows прямой Node-запуск не зависит от политики выполнения `.ps1`.

Новый проект получает `.agent/GETTING-STARTED.md`, references, `CONTEXT.md`, ADR-шаблон и инструменты. Из существующего `package.json` предлагаются объявленные команды `dev/build/test/check/typecheck/lint` с учётом lockfile. Они **не выполняются** установщиком. Для других стеков заполните conventions по существующей конфигурации.

## Языки и настройка силами агента

Выберите `--language en|ru`: новая неинтерактивная установка использует английский, обновления сохраняют записанный язык. Все встроенные инструкции имеют обе версии; `.agent/translations/en/` и `ru/` содержат справочные копии вне поиска ресурсов. В нативные каталоги навыков и шаблонов ставится только выбранный язык. Нативный npm-пакет Pi использует английские оригиналы; для русского используйте проектный `setup --language ru`.

Для настройки агентом дайте ему [SETUP.ru.md](SETUP.ru.md) или вызовите установленный навык `agent-kit-setup`. Он охватывает изучение, preview, разрешённое применение, команды проекта, doctor и итоговый отчёт. Для смены языка просмотрите `--language en --force --dry-run`, затем выполните без `--dry-run`. Пользовательские CONTEXT, conventions и другие сохраняемые справки автоматически не переводятся и не перезаписываются. Флаги CLI, коды диагностики, ключи JSON и сторонние источники сохраняют исходные идентификаторы и язык.

## Предсказуемое обновление и откат

- Существующие настройки клиентов остаются побайтно прежними, включая модель, провайдера, permissions и compaction.
- В AGENTS/CLAUDE добавляется блок `AGENT-KIT`; обновление блока требует `--force`, окружающий текст сохраняется. Активный непустой `AGENTS.override.md` учитывается для Pi/Codex. Пользовательские CONTEXT, ADR и conventions не заменяются даже с `--force`.
- Существующие одноимённые папки навыков сохраняются целиком. `--force` обновляет файлы комплекта с резервной копией, оставляя посторонние файлы.
- `--dry-run` не создаёт даже целевой каталог. Все изменения одной установки, включая выбранный Pi addon, входят в один manifest.
- `.agent/kit.json` хранит выбор адаптеров, язык и хеши установленных файлов. `doctor --json` пригоден для скриптов; ошибки дают код 1, предупреждения — 0.

Обновление: та же команда с `--force --dry-run`, затем после просмотра — с `--force`. Удаление/откат выполняется по manifest из вывода установки:

```sh
node scripts/agent-kit.mjs restore --target ../my-project --manifest ../my-project/.pi-starter-backups/RUN/manifest.json --dry-run
node scripts/agent-kit.mjs restore --target ../my-project --manifest ../my-project/.pi-starter-backups/RUN/manifest.json
```

Откатывайте последовательные установки в обратном порядке. Поздние пользовательские изменения блокируют откат; они не стираются. Пустые папки и резервные копии остаются. При миграции с v2.1 используйте `setup`, а не `init --force`. Глобальные навыки Pi из прежней установки могут перекрываться с `deep`; проверьте старым `scripts/doctor.mjs`.

## Совместная работа клиентов

Pi/Codex/OpenCode используют одну папку `.agents/skills`; Claude получает обычные копии из того же исходника. Симлинки не требуются. OpenCode может предупреждать об одинаковых именах из `.agents` и `.claude`: одинаковое содержимое эквивалентно, но при различиях приоритет зависит от версии. `doctor` считает различающиеся копии ошибкой; синхронизируйте осознанные изменения перед переключением агента. Альтернатива — устанавливать адаптеры в отдельных рабочих копиях.

Инструкции внутри вложенных модулей, глобальные правила и отключённые пользователем skills могут менять поведение клиента. После изменения оснастки перезапустите клиента, если он не обнаружил новые ресурсы. Doctor проверяет проектные файлы, но не подтверждает загрузку клиентом и не сканирует все глобальные настройки.

## Полная оснастка Pi

Все прежние `global`, `init`, `matt`, `context-tools`, `restore`, `/efficient-*` и `/portable-handoff` сохранены. Опциональный profile agenticoding по-прежнему требует явного выбора и проверки; основной режим сохраняет автоматическую compaction.

```sh
node scripts/agent-kit.mjs setup ../my-project --agents pi --with-context-tools
```

В доверенном интерактивном Pi: `/reload`, затем `/context-tools status`. Guard начинает в режиме предупреждения, делегирование выключено. Пользователь включает его через `/context-tools enable`, выбирая модель и разрешённые пути. Подробности и ограничения: [CONTEXT-TOOLS-RU.md](CONTEXT-TOOLS-RU.md).

Комплект также имеет нативный Pi package manifest. Вместо проектных копий skills/prompts можно отдельно подключить локальную папку:

```sh
pi install /absolute/path/to/kit -l
```

Это альтернативный способ подключения ресурсов, а не второй обязательный шаг после `setup`: одновременное использование даёт дубли. Он включает portable и расширенные skills, все prompts, но не расширение context-tools и не проектные helpers. Для полноценной оснастки предпочтителен `setup`. Локальная папка пакета должна оставаться доступной. [Контракт Pi packages](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md).

Имя npm-пакета сохранено ради совместимости; bin называется `agent-kit`. Можно собрать локальный архив командой `npm pack --ignore-scripts`. Пакет не опубликован в registry; команды вида `npx agent-kit` из интернета не являются способом установки этой версии.

## Оптимизация контекста

Вместо автоматического пересказа исходников по умолчанию используются точные диапазоны, ограниченные логи, небольшой стабильный policy и четыре конкретных навыка. Английская общая инструкция и метаданные lean ограничены 1 KiB каждый; UTF-8-бюджеты русского языка проверяются отдельно. Изменяемый статус хранится в handoff, а не в постоянных инструкциях.

Из корня подготовленного проекта:

```sh
node .agent/scripts/context-pack.mjs --file src/main.ts --range 20:90 --file tests/main.test.ts --max-bytes 16384 --out .agent/tmp/context.json
node .agent/scripts/context-pack.mjs --verify .agent/tmp/context.json
```

Без `--range` берётся весь файл. Бюджет учитывает весь сериализованный JSON в UTF-8; превышение завершает команду без выдачи частичного текста. Допускается до 16 файлов и 2 MiB локального сканирования каждого. Хеш охватывает весь исходник, поэтому изменение вне выбранного диапазона тоже делает пакет устаревшим. Новый `--out` не перезаписывает существующие файлы. Пакет не отправляется модели автоматически.

Имена известных credential/config-путей исключены; это не распознавание всех секретов внутри исходников. Проверка пакета подтверждает происхождение и текст выдержек, а не смысл ответа. Байты не равны токенам. Влияние на качество, стоимость и задержку оценивайте по [EVALUATION.md](EVALUATION.md); обещаний процента экономии нет.

## Проверка живых клиентов

В этой рабочей среде проверен настоящий SDK Pi 0.85.1: загрузка project skills/prompts, регистрация optional context-tools, handler `status` с перехваченным UI callback и отдельное подключение локального Pi package. Вызовов модели — 0. Это подтверждает загрузчик и регистрацию, но не полноценную TUI/provider-сессию. Повторяемая проверка: `node scripts/smoke-pi.mjs --sdk /path/to/@earendil-works/pi-coding-agent`; скрипт требует заранее установленный локальный SDK, сам ничего не скачивает. [Результаты проверки](verification/universal-v2.2.md).

Для каждого выбранного агента в тестовом проекте проверьте: обнаружены инструкции и четыре навыка; первый запрос читает нужный файл и запускает ожидаемый тест; пакет контекста проходит проверку, а после изменения исходника — не проходит; handoff сохраняет точную следующую задачу. Для Pi дополнительно проверьте status/warn, однократный full-read, отзыв согласия и выбранный provider. Отсутствующую авторизацию помечайте как «не проверено», а не успех.
