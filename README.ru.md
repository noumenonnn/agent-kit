# Agent Kit — v2.2 (Pi Token-Efficient Starter Kit)

[English](README.md) · [GitHub](https://github.com/noumenonnn/agent-kit) · [MIT](LICENSE)

Офлайн-оснастка для **Pi, Codex, Claude Code и OpenCode**: установка в новый или существующий проект, навыки по требованию, точный контекст и проверяемые изменения. Pi сохраняет все прежние команды, prompts, профили и опциональное расширение context-tools. Обновлено 8 сентября 2026 года.

## Начать за одну команду

Нужен Node.js >=22.19.0. Из папки комплекта:

```sh
npm run setup -- --target ../my-project --agents all
```

Каталог проекта может уже существовать или будет создан. Для одного агента укажите `--agents pi`, `codex`, `claude` или `opencode`; можно перечислить через запятую. Без выбора используется Pi. Добавьте `--dry-run`, чтобы сначала увидеть все изменения без записи.

Предпочитаете пошаговый выбор: `npm run wizard`. На Windows с заблокированными PowerShell-скриптами используйте `npm.cmd run wizard` или напрямую `node scripts/agent-kit.mjs wizard`; менять execution policy не нужно.

```sh
npm run doctor -- --target ../my-project
```

Откройте проект в выбранном агенте и выполните первый запрос:

| Агент | Начало работы |
| --- | --- |
| Pi | `/efficient-task Добавь X; проверь Y` |
| Codex | `$efficient-task Добавь X; проверь Y` |
| Claude Code | `/efficient-task Добавь X; проверь Y` |
| OpenCode | `/efficient-task Добавь X; проверь Y` |

Проектная памятка появится в `.agent/GETTING-STARTED.md`. Установщик сохраняет ваши настройки, добавляет короткий помеченный блок инструкций и резервирует изменяемые файлы. Он не устанавливает клиенты, не запускает модели и не требует API-ключей. Новый `setup --force` обновляет только свой блок в AGENTS/CLAUDE; окружающие правила сохраняются.

## Контекст и возможности

По умолчанию устанавливаются три навыка: выполнение задачи, точные выдержки из исходников и передача работы между сессиями. `--preset deep` добавляет шесть специальных навыков. Пакет контекста формируется локально из явных файлов/диапазонов, проверяет свежесть по SHA-256 и отказывает при превышении бюджета. Полные логи проверок остаются доступны, а вывод в контекст ограничен.

Общие инструменты работают во всех четырёх агентах. Нативный перехват больших чтений и модельный bulk-reader предоставляются **Pi context-tools**, отдельно через `--with-context-tools`. У остальных адаптеров нет скрытых hooks или переключений модели. В комплекте нет обязательных внешних зависимостей.

**[Полное руководство: установка, обновление, откат, матрица поддержки](UNIVERSAL-RU.md)** · **[Исследование Portal и аналогов](RESEARCH-UNIVERSAL-RU.md)** · **[Как измерять качество и экономию](EVALUATION.md)**.

Ниже — совместимый интерфейс Pi из v2.1. Для новых установок предпочтителен `setup`; старые `init`, `global`, `matt`, `context-tools`, `restore` продолжают работать. Правила `init --force` отличаются от нового безопасного слияния `setup`.

## Новое в v2.1

- **Опциональный context guard**: байтовый бюджет запрошенного `read`, режимы warn/enforce и одноразовое разрешение точного полного чтения.
- **Bulk-reader**: один tool-less вызов выбранной модели через Pi, только после интерактивного подтверждения модели/папок. Проверяются пути, строки, цитаты и свежесть исходников; это не semantic verifier.
- **Учёт worker usage и сравнение трёх режимов**: receipts, неизвестная стоимость не заменяется нулём, валидатор запрещает повторно прибавлять worker к Pi total.

Модуль **не устанавливается командой `init` и не включается автоматически**. Core работает как раньше, постоянный AGENTS-контекст не увеличен. Нет Portal/AiKA и code-writer. Это оригинальная реализация идей Spotify shunt, а не копия его кода.

```bash
node scripts/kit.mjs context-tools --target /path/to/project --dry-run
node scripts/kit.mjs context-tools --target /path/to/project
```

Затем в доверенном интерактивном Pi: `/reload` → `/context-tools status` → `/context-tools enable`. Включение требует выбора провайдера/модели и подтверждения разрешённых путей. По умолчанию guard только предупреждает; отправки к модели нет. Для миграции с v2 не нужен `init --force`.

**Подробно, включая Windows, ограничения и отключение:** `CONTEXT-TOOLS-RU.md`. Проверки выполнены офлайн; реальная Pi/provider интеграция и native Windows/macOS требуют smoke-теста. Процент экономии не заявляется.

## Прежний быстрый старт Pi

Требования: Node.js **≥22.19.0**, Git; ripgrep полезен. Рекомендованный Pi **0.85.1** — версия из официального релиза от 5 сентября 2026. Совместимость настроек сверена по документации; ограничения выполненных тестов — в `AUDIT-RU.md`.

При необходимости установите Pi отдельно, осознанно разрешая сетевую установку:

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent@0.85.1
pi --version
```

Из распакованного комплекта, одинаково в Bash и PowerShell:

```bash
node scripts/check-kit.mjs
node --test
node scripts/kit.mjs global --dry-run
node scripts/kit.mjs global
node scripts/kit.mjs init --target /path/to/your-repository --dry-run
node scripts/kit.mjs init --target /path/to/your-repository
node scripts/doctor.mjs --project /path/to/your-repository
```

В Windows используйте путь вроде `"C:/work/my project"`. Проект должен находиться **вне каталога комплекта**. Сохранены тонкие обёртки `.sh` и `.ps1`, но вся логика теперь общая, на Node.

Перед работой заполните команды тестов/типизации/сборки в `.agent/references/conventions.md`, уточните `CONTEXT.md`. Откройте Pi из корня проекта, проверьте предлагаемые ресурсы перед доверием, выполните `/login`, если нужно. После изменения решения через `/trust` перезапустите Pi; `/reload` перечитывает уже доступные ресурсы.

```text
/efficient-task Добавь проверку X; критерий — тест Y проходит
```

## Установка без потери ваших изменений

- `global` не запускает Pi/npm/npx и не устанавливает расширений. Соблюдает `PI_CODING_AGENT_DIR`; `--pi-home DIR` имеет приоритет.
- По умолчанию существующие файлы и целые папки одноимённых навыков сохраняются.
- `--force` обновляет файлы комплекта с резервной копией, **не удаляет** ваши дополнительные файлы. Проектный `AGENTS.md` при `--force` заменяется целиком: для персональных правил предпочтите ручное слияние.
- В глобальном `AGENTS.md` обновляется только помеченный блок; текст до/после сохраняется. Без `--force` старый блок остаётся нетронутым.
- Существующий `settings.json` меняется **только с `--apply-settings`**. Глубокое слияние сохраняет неизвестные поля, но явно устанавливает пять управляемых настроек шаблона: thinking, cache notices, project trust, skill commands и compaction. Перед применением просмотрите шаблон.
- Правила логов, handoff и резервных копий добавляются в настоящую `.gitignore`, без удаления её содержимого. Уже отслеживаемые Git файлы это не снимает с учёта.
- Каждая запись предваряется проверкой путей. Симлинки/junction внутри целевой директории отвергаются. Это локальная защита установки, не барьер против враждебного параллельного изменения файловой системы.
- `--dry-run` ничего не создаёт, даже целевую папку. Для реальных изменений сохраняется manifest с SHA-256 и исходными байтами в `.pi-starter-backups/`.

Откат (подставьте путь manifest из вывода установки):

```bash
node scripts/kit.mjs restore --target /path/to/repo --manifest /path/to/repo/.pi-starter-backups/RUN/manifest.json --dry-run
node scripts/kit.mjs restore --target /path/to/repo --manifest /path/to/repo/.pi-starter-backups/RUN/manifest.json
```

Откат откажется затирать файлы, изменённые после установки. Если локальная установка была прервана, сначала убедитесь, что она не работает, затем разберите оставшийся lock/manifest; не удаляйте lock действующего процесса. Откат сохраняет пустые папки и резервные копии.

## Core и agenticoding — разные режимы

| | Core — по умолчанию | Опциональный agenticoding |
|---|---|---|
| Авто-сжатие | Включено | Отключается явно, после проверки handoff |
| Переключение модели | Вручную через `/model` | `model-group` в шаблонах |
| Spawn / notebook / handoff | Не обещаются | Да, через расширение |
| Метаданные `readonly`, `thinking` | Не гарантируют поведение | Обрабатывает расширение |
| Изоляция ОС | Нет | Также не гарантируется |

Расширение **не обязательно**. Чтобы сохранить ваш исходный сценарий:

1. Проверьте исходники/README `pi-agenticoding@0.5.0`, затем отдельно выполните `pi install npm:pi-agenticoding@0.5.0`.
2. Перезапустите Pi; проверьте `/model-groups`, `/readonly`, `/handoff` в тестовом репозитории. Не отключайте compaction до проверки.
3. Создайте роли из `MODEL-ROUTING.md`. Начните с одной модели на роль.
4. Явно примените профиль:

```bash
node scripts/kit.mjs global --profile agenticoding --ack-agenticoding --apply-settings --dry-run
node scripts/kit.mjs global --profile agenticoding --ack-agenticoding --apply-settings
```

Установщик требует точную включённую запись расширения в глобальных settings. Это проверка декларации, **не доказательство работоспособности расширения**. Если оно установлено только на уровне проекта, глобальный профиль намеренно не меняется: настройте локальный compaction вручную только для этого проекта после smoke-теста.

Вернуться к безопасным core-настройкам: `node scripts/kit.mjs global --profile core --apply-settings`. Это не удаляет установленное расширение, а восстанавливает core-defaults; для его удаления используйте средства Pi.

## Рабочие сценарии

- **Маленькая понятная задача:** `/efficient-task` → изменение + проверки + отчёт в одном контексте.
- **Незнакомый код:** `/efficient-discover` → `/efficient-build` → `/efficient-verify`.
- **Значимый риск:** дополнительный `/efficient-review`; независимость требует отдельного контекста, не только смены модели.
- **Архитектурный вопрос:** `/efficient-architecture`, без автоматического переписывания проекта.
- **Передача работы:** `/portable-handoff [path]` пишет краткий документ; по умолчанию `.agent/handoffs/latest.md`. Не сбрасывает сессию.

Не вызывайте все шаблоны подряд по привычке. `/handoff` расширения и `/compact` ядра не нужны после каждого шага. Handoff создаёт новый префикс и может потерять выгоду от кэша.

В Pi навыки вызываются как **`/skill:name`**, например `/skill:tdd`. Наши файлы в `.pi/prompts/` — это шаблоны и вызываются `/efficient-task`, без `skill:`. Подробнее: `MATT-POCOCK-INTEGRATION.md`.

## Компактные, но честные логи

Из репозитория:

```bash
node .agent/scripts/compact-run.mjs --timeout-ms 120000 -- pnpm test
node .agent/scripts/compact-run.mjs --timeout-ms 300000 -- npm run build
node .agent/scripts/diff-summary.mjs
node .agent/scripts/diff-summary.mjs --base origin/main --no-log
```

На Windows `.cmd`-команды (npm/pnpm) запускайте через **явно выбранную** оболочку либо через их JS entry point. Например:

```powershell
node .agent/scripts/compact-run.mjs --timeout-ms 120000 -- powershell.exe -NoProfile -NonInteractive -Command "pnpm test"
```

Обёртка не добавляет shell автоматически. Не вставляйте непроверенный текст в явную shell-строку.

Свойства `compact-run`:
- Потоковая запись, ограниченная память выдержек; stdout/stderr сохраняются в порядке получения событий, без обещания абсолютного порядка между потоками.
- По умолчанию ≤8192 байт ответа, ≤64 MiB сырого лога, 120 секунд. Настройки: `--max-output-bytes`, `--max-log-bytes`, `--timeout-ms`; превышение лимита лога явно отмечено.
- Уникальный каталог `.agent/tmp/run-…/`, `output.log` и `result.json`; аргументы команды намеренно не выводятся.
- Код процесса сохраняется; timeout — 124, ошибка журналирования — 125, запуск — 126/127, сигналы — 128+номер.
- POSIX: остановка группы процессов с эскалацией; Windows: best-effort `taskkill /T /F`. Отделившиеся фоновые процессы не гарантированно контролируются. Не используйте для серверов/интерактивных установщиков.
- `OK` означает exit 0, **не PASS задачи**. Проверяйте обнаружение тестов, assertions, coverage по изменённому поведению и критерии приёмки.

`diff-summary` включает untracked/staged/unstaged; `--base REF` дополнительно учитывает закоммиченные изменения от merge-base. Имена обрабатываются через NUL-разделители. Полный JSON сохраняется на диск; `--no-log` этого не делает. Конфликты дают ненулевой код. Категории могут пересекаться; переименование считается одной записью. Submodules не раскрываются рекурсивно.

## Безопасность и ограничения

**Trust ≠ sandbox.** Pi загружает AGENTS-контекст независимо от project trust, если context loading не отключён. `readonly` расширения — guardrail; Windows использует классификатор команд. Для недоверенного кода нужны ограничения ОС/контейнер/VM и минимум секретов/сетевого доступа.

Spawn изолирует **контекст, не рабочее дерево**. Один writer на общий cwd; настоящая параллельная разработка требует отдельных worktrees/branches и последовательной интеграции. Проверки тоже могут писать caches/snapshots.

Сырые логи/бэкапы могут содержать секреты. Gitignore и права 0600 на POSIX — не шифрование. Не загружайте их целиком в чат. Автоматического всестороннего редактирования секретов здесь нет.
