# Навыки Matt Pocock и Pi

[English](MATT-POCOCK-INTEGRATION.md)

Сохраняйте повторно используемые инженерные подходы Matt, не дублируя их вторым большим фреймворком. Навыки комплекта отвечают за контекст, безопасные детерминированные действия и свидетельства.

## Правильный вызов в Pi

Pi регистрирует навыки как `/skill:name`:

```text
/skill:setup-matt-pocock-skills
/skill:tdd
/skill:diagnosing-bugs
/skill:code-review
```

Примеры `/tdd` или `/grill-with-docs` в upstream README могут относиться к другому клиенту или aliases. Шаблоны запросов Pi, в отличие от навыков, действительно вызываются как `/name`.

**В core Pi нет встроенного конфликта** между `/handoff` расширения и `/skill:handoff` Matt. Их смысл различается. Старый комплект исключал handoff Matt из-за слишком широкого предположения о конфликте. Он опционален в deep; `portable-handoff` доступен без Matt. Если добавляете сторонние aliases, перепроверьте разрешение имён.

## Только проверенный локальный источник с фиксацией коммита

Прежний bootstrap `npx skills@latest ... --yes` удалён: он запускал плавающий CLI на меняющемся репозитории. Новый скрипт не скачивает и не выполняет код; он читает обычные Git blobs из явно указанного полного SHA коммита.

Получите официальный checkout отдельно с разрешением на сеть и изучите выбранную ревизию:

```bash
git clone https://github.com/mattpocock/skills.git /path/to/matt-skills
git -C /path/to/matt-skills rev-parse HEAD
```

Проверьте `LICENSE`, тела навыков и скрипты этого коммита. Подставьте проверенный SHA из 40 символов, а не `main`:

```bash
node scripts/kit.mjs matt --source /path/to/matt-skills --ref FULL_REVIEWED_COMMIT_SHA --target /path/to/repo --dry-run
node scripts/kit.mjs matt --source /path/to/matt-skills --ref FULL_REVIEWED_COMMIT_SHA --target /path/to/repo
```

Аудит не объявляет какой-либо коммит целиком проверенным: изучен upstream README, а не каждый исполняемый файл актуального дерева. В `versions.json` намеренно стоит null. Локальный SHA фиксирует содержимое, но не доказывает происхождение или безопасность.

- **lean по умолчанию:** настройка, TDD, отладка, проектирование модулей, ревью, доменная модель, writing-for-agents — семь навыков.
- **deep (`--preset deep`):** добавляет процессы требований, спецификаций, задач, исследования и продуктивности из исходной интеграции, а также handoff с явным пространством имён. Устанавливайте их при необходимости.
- Структура источника проверяется; отсутствие навыка вызывает явный отказ до записи. Скрытой подмены версии нет.
- Существующие папки навыков сохраняются без `--force`; изменения резервируются, дополнительные файлы пользователя не удаляются.
- Скрипты, assets и LICENSE копируются без выполнения; происхождение записывается в `.pi/matt-pocock-source.json`, хеши файлов — в manifest установки.
- Незакоммиченные изменения источника не копируются: только blobs указанного коммита.
- Не устанавливайте те же имена одновременно в `.agents/skills`, каталог другого клиента или плагин. Pi обнаруживает несколько путей; при конфликте оставляет один и предупреждает.

Запустите `/skill:setup-matt-pocock-skills` **после его проверки**, один раз на репозиторий, чтобы выбрать расположение трекера и документов. Процесс может запросить или выполнить дополнительную настройку: установка сама по себе не разрешает внешнюю публикацию или credentials.

## Ответственность за этап

- Небольшая ясная правка: `/efficient-task` и только применимые подходы.
- Неясные требования при установленном deep: `/skill:grill-with-docs`, затем реализация после уточнения намерения.
- Стабильная точка воспроизведения ошибки: `/skill:diagnosing-bugs` или `/skill:tdd`.
- Архитектурная граница: `/skill:codebase-design`.
- Значимое ревью: один ответственный процесс, без механического повторения всей lean-цепочки после `/skill:implement`.

Межклиентские навыки могут ссылаться на отсутствующие в Pi инструменты и подагентов. Адаптируйте метод к доступным возможностям; не выдумывайте вызовы и не заявляйте скрытую фоновую работу. Сохраняйте upstream `disable-model-invocation`. Оркестрация по запросу пользователя должна оставаться такой, а не превращать каждую задачу во фреймворк.

## Обновление

Самостоятельно получите и проверьте новый коммит, повторите dry-run с новым SHA, изучите diff и резервную копию. `npx skills update` относится к установкам того CLI, а не локальным Git-blob-копиям комплекта. Если предпочитаете upstream CLI, используйте его отдельно с проверенными версией/источником и учётом lock/provenance; не смешивайте способы управления одними именами навыков.
