# Аудит и улучшения Pi Starter Kit

**Дата:** 6 сентября 2026. **Результат:** версия 2.0.0, готовая к локальной установке после просмотра изменений.

## Итог

Идея исходного комплекта правильная: короткий AGENTS, поиск перед чтением, навыки по необходимости, детерминированная проверка, внешние журналы и экономное использование сильных моделей. Перестройка в тяжёлый multi-agent framework не нужна.

Главные проблемы были не в отсутствии модных инструментов, а в безопасной установке, ограничениях вывода, корректности проверок и скрытой зависимости от расширения. Они исправлены в коде, а не только описаны советами.

## Существенные исправления

| Приоритет | Что было | Что сделано |
|---|---|---|
| Высокий | Global installer удалял существующую папку навыка через rm -rf / Remove-Item | Сохранение по умолчанию, force только с побайтовым бэкапом; дополнительные файлы не удаляются |
| Высокий | Compaction выключался даже с SkipAgenticoding | Core сохраняет auto-compaction; альтернативный профиль требует явного подтверждения и точной декларации расширения |
| Высокий | Неявный shell на Windows менял смысл аргументов и создавал риск интерпретации метасимволов | Встроенного shell нет; .cmd-инструменты запускаются только через явно выбранную оболочку/JS entry point |
| Средний | compact-run накапливал весь stdout/stderr в строке, ограничивал только число строк | Потоковый лог, ограниченные выдержки/длина строки/байты ответа, лимит лога, явный признак неполноты |
| Средний | Не было timeout/надёжного статуса сигналов; process.exit мог обрывать выдачу stdout | Дедлайн, POSIX process-group termination, Windows best-effort taskkill, реальные exit codes; завершение через exitCode |
| Средний | init-project.sh менял cwd до разрешения относительного пути; --force зависел от позиции | Общий Node installer, разрешение пути до обхода, явный разбор аргументов, dry-run |
| Средний | .gitignore существовал только как неактивный snippet | Аддитивное слияние с настоящей .gitignore; логи, handoff и бэкапы действительно игнорируются |
| Средний | CHANGED FILES не включал untracked, имена разбирались по строкам | NUL-safe Git parsing, staged/unstaged/untracked/conflicts, merge-base review, ограниченный вывод и полный JSON |
| Средний | Verify назывался read-only, хотя тесты/сборки пишут артефакты | Явное readonly:false для task/build/verify, запрет autofix/snapshot updates без отдельного разрешения |
| Средний | Метаданные расширения и обычные Pi templates смешивались | Явно описано: без расширения это не автоматический routing и не защита; core работает самостоятельно |
| Средний | Документация навыков использовала /tdd и заявляла неизбежную коллизию handoff | Канонические /skill:tdd и /skill:handoff; они отличаются от extension /handoff |
| Средний | npx skills@latest с --yes запускал движущийся installer и источник | Опциональный offline перенос Git blobs из выбранного полного commit SHA, копирование лицензии и provenance |
| Средний | Spawn мог восприниматься как изоляция файлов, trust/readonly — как sandbox | Политика одного writer на cwd; отдельные worktrees для параллельных правок; явные ограничения безопасности |
| Улучшение | Метрика input tokens / completed task не учитывала полностью качество и кэш | Cost/time per accepted task + acceptance/regression gates; учитываются дети, retries, review, cache и вмешательства |
| Улучшение | Для простого изменения предлагалась цепочка фаз и переключений | Один /efficient-task по умолчанию; дополнительные фазы по сложности/риску |
| Улучшение | Не было автоматических проверок инфраструктуры комплекта | Node regression suite, static checker, doctor и CI-матрица с immutable action pins |

## Что соответствует актуальной практике

- **Версионная граница, а не “latest” в командах:** Pi 0.85.1 из официального релиза от 5 сентября; Node ≥22.19.0. Опциональный pi-agenticoding остаётся на проверенной по package README версии 0.5.0, вместо необоснованного апгрейда.
- **Progressive disclosure и стабильный префикс:** постоянный policy-контекст уменьшен с **2815 до 2407 UTF-8 байт**. Это не токены модели и не доказательство экономии денег. Отчёты, тесты и подробные safety-правила остаются “холодными” файлами.
- **Качество прежде экономии:** не обрезать важную диагностику и не считать exit 0 доказательством тестового покрытия. Нет выдуманного процента экономии.
- **Обоснованная оркестрация:** подагент — для ограниченной задачи/изоляции контекста, а не для одного grep; handoff не сохраняет старый cache prefix. Группа моделей расширения не является ordered failover.
- **Воспроизводимость и обратимость:** точные версии/commit, резервные копии, SHA-256 manifests и откат, отказывающийся стирать более поздние изменения пользователя.
- **Настоящие границы доверия:** недоверенные репозитории/расширения исполняются в контейнере/VM/ограниченной учётной записи, не “защищаются” только текстом промпта.

## Проверки, реально выполненные

Среда: **Linux, v24.14.1**. Это проверки инфраструктуры самого комплекта, не тесты вашего будущего проекта.

- `node --test --test-reporter=tap`: **40 из 40 PASS**, 0 FAIL, 0 skipped.
- `node scripts/check-kit.mjs`: PASS — синтаксис JS, JSON, frontmatter, явные readonly-настройки, profiles и бюджет постоянных инструкций.
- `bash -n scripts/*.sh`: все три обёртки проверены по отдельности; Bash wrapper также запущен в тесте.
- Регрессии: повторная установка, пользовательские skills/settings, глубокое слияние, бэкап/откат, отказ на новых правках, malformed markers, symlink escape, install lock, отсутствие floating ref, перенос Git blobs без выполнения, UTF-8/ANSI, большой однострочный вывод, реальные exit codes, timeout/SIGINT/дочерние процессы, staged/unstaged/untracked, rename, merge-base, merge conflicts, пути с пробелами и static doctor.

Отдельно воспроизведены дефекты исходника: удаление custom-файла навыка, выключенное compaction без расширения, untracked с CHANGED FILES (0), неработающий gitignore и чрезмерный вывод одной длинной строки. Для того же входа в 200 000 символов v2 вернула **1055 байт** summary и сохранила журнал. Это функциональная проверка ограничителя, не benchmark стоимости модели.

Сырые результаты: `verification/test-output.tap`, `verification/RESULTS.json`, `verification/original-regressions.json`, `verification/static-checks.json`.

## Что НЕ проверено и почему

- В sandbox нет установленного Pi и прямого сетевого доступа для npm/GitHub из terminal. Поэтому **не выполнялись** живые входы к провайдерам, маршрутизация моделей, загрузка расширения, readonly-переходы и handoff. Их контракты сверены с доступными первоисточниками, но это не runtime verification.
- **Windows/PowerShell и macOS не запускались.** Обёртки используют общий Node-код; CI-матрица подготовлена, но ещё не выполнялась. Windows process termination остаётся best-effort. Symlink-тесты могут требовать соответствующих прав на Windows.
- Не запускались реальные upstream Matt skills и их программы; не заявляется сквозная совместимость каждого workflow с Pi. Installer проверен на собственных Git fixtures, без выполнения внешнего кода.
- Не измерялась экономия на ваших настоящих задачах и моделях. `EVALUATION.md` содержит протокол такого сравнения.
- Не выполнялся полноценный adversarial security audit. Локальные path guards/locks не защищают от враждебной гонки файловой системы; сырые логи/бэкапы не шифруются и могут содержать секреты.

## Рекомендуемый следующий шаг

Начните с core, примените dry-run и заполните реальные команды проекта. Проведите одну небольшую задачу с известным тестом. Затем при необходимости отдельно проверьте profile agenticoding и добавьте только действительно нужные Matt skills. Для перехода с уже установленного v1 используйте `MIGRATION-RU.md`: сохранение старых файлов по умолчанию означает, что их нужно осознанно обновить/слить, а не считать автоматически исправленными.

Полная документация — `README.md`; источники с границей проверки — `SOURCES.md`. Все изменения приложены как `CHANGES.patch` и список хэшей, чтобы их можно было проверить до установки.
