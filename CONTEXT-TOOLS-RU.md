# Context tools v0.1 — опциональный модуль для kit v2.1

[English](CONTEXT-TOOLS.md)

Это MVP, вдохновлённый архитектурой Spotify shunt, **не порт его кода**. Он добавляет контроль больших `read` и узкий `bulk_read` через выбранную вами модель Pi. Portal/AiKA, Bash/jq и второй агентный фреймворк не нужны. Code-writer в эту версию не входит.

**Историческая проверка v2.1:** локальная логика, установщик и адаптер проверены офлайн с имитацией Pi/model responses. TypeScript проверен на синтаксис. Реальная загрузка в Pi, платные провайдеры и native Windows/macOS в этой среде не запускались. Первое подключение — в тестовом репозитории. Core сохраняет самостоятельность, настройки compaction не меняются.

Более поздние свидетельства загрузки ресурсов приведены отдельно в [verification](verification/README.ru.md).

## 1. Установка

Распакуйте новый архив **отдельно** от старого kit и рабочего проекта. Если core v2 уже установлен в проект, переустанавливать глобальные AGENTS/skills или делать `init --force` не нужно.

Из каталога kit:

```bash
node scripts/check-kit.mjs
node --test
node scripts/kit.mjs context-tools --target /path/to/project --dry-run
node scripts/kit.mjs context-tools --target /path/to/project
```

Windows / PowerShell (замените путь проекта):

```powershell
$Kit = "$HOME\Tools\pi-token-efficient-starter-kit-v2.1"
$Project = "C:\work\my-project"
node "$Kit\scripts\kit.mjs" context-tools --target $Project --dry-run
node "$Kit\scripts\kit.mjs" context-tools --target $Project
Set-Location $Project
pi.cmd
```

Требования остаются прежними: Node ≥22.19, Git, Pi. Рекомендованная версионная граница — Pi 0.85.1; код проверяет наличие необходимой возможности отправки через реестр моделей. Для новой установки Pi на Windows: `npm.cmd install -g --ignore-scripts @earendil-works/pi-coding-agent@0.85.1`. Администратор и изменение ExecutionPolicy не нужны для команд Node/npm.cmd/pi.cmd.

Установщик **офлайн**: копирует только `.pi/extensions/pi-context-tools/index.ts`, три файла `lib/*.mjs`, `.pi/context-tools.json` и недостающие правила `.gitignore`. Не запускает расширение, npm или модель. Ничего не отправляет. Не устанавливайте отдельно TypeBox: его импорт и типы расширений должны предоставляться загрузчиком Pi.

Перед доверием проекту просмотрите код расширения. В уже доверенном проекте используйте `/reload`; после изменения trust перезапустите Pi. Установка сама trust не повышает.

## 2. Первое включение

```text
/context-tools status
/context-tools enable
```

В интерактивном терминале:

1. Выберите провайдера и конкретную модель среди доступных авторизованных моделей Pi. Ограничение `scopedModels`, если задано, соблюдается. Выбор основной модели автоматически не меняет worker.
2. Введите JSON-массив реальных путей, например `["src","tests"]` или `["package.json"]`. Пути относительно текущего проекта. Весь корень, glob и выход за проект не разрешаются.
3. Проверьте показанные проект, endpoint origin, модель, папки и лимиты. Подтвердите отправку **выбранных исходников и вопроса** этому провайдеру. Проверьте папки на встроенные секреты заранее.

Для минимального smoke-теста можно разрешить один проверенный небольшой файл и попросить Pi ответить на конкретный вопрос по нему через `bulk_read`. В обычной работе маленькие файлы дешевле читать напрямую; smoke-тест не является доказательством экономии.

При отсутствии подходящей авторизации используйте `/login` Pi и повторите выбор. Ключи не вводятся в команды модуля и не сохраняются им. Неподдерживаемая возможность Pi означает отказ включения, а не переход на другой клиент/провайдер.

Разрешение хранится только в памяти сессии. `/reload`, новая сессия, switch/fork/tree/shutdown и `/context-tools disable` отзывают его. Незавершённый диалог подтверждения не переносится в новую сессию. В print/json/RPC автоматическое включение не поддерживается. Редактирование `context-tools.json` не может включить делегирование.

## 3. Контроль чтения

| Команда | Поведение |
|---|---|
| `/context-tools warn` | Предупреждение в UI, исходный `read` не меняется. Это наблюдение, не гарантированная экономия. |
| `/context-tools enforce` | Блокирует измеренные чтения сверх байтового бюджета. Не запускает worker автоматически. |
| `/context-tools off` | Отключает только read guard; уже разрешённый worker остаётся включённым. |
| `/context-tools allow-read` | Диалог разрешения одного большого чтения указанного пути. Не даёт разрешение на worker. |
| `/context-tools disable` | Отключает worker и отменяет его активный запрос; guard остаётся в выбранном режиме. |

По умолчанию — `warn`, 16 384 байта. Проверяется **запрошенный диапазон**, а не только число строк: одна длинная minified-строка тоже считается большой. Наличие `offset` без реального уменьшения диапазона не является исключением. Маленький диапазон большого файла остаётся доступным.

Сканирование ограничено 2 MiB. Если далёкий offset не измерить в этом объёме, возвращается предупреждение, но чтение допускается даже в enforce. Изображения известного формата, недоступные и неподдерживаемые пути не перехватываются. Подсчёт — байты локального текста, **не точные токены и не точный размер Pi tool-result с оформлением**.

Это guard для локального штатного `read`, **не sandbox и не общий перехват вывода**. Bash/PowerShell, другие/переопределённые инструменты и удалённые файловые системы могут его обходить. Не обходите бюджет shell-командой ради самого обхода: выберите grep/rg, нужный диапазон, либо явно разрешённый worker. Существующие собственные ограничения вывода Pi продолжают действовать.

## 4. Контракт bulk-reader

Pi получает инструмент `bulk_read` с таким запросом (пути в примере надо заменить на реальные):

```json
{
  "question": "Где определяется лимит повторов и кто его использует?",
  "files": [
    {"path": "src/retry.ts", "offset": 1, "limit": 120},
    {"path": "src/client.ts", "offset": 40, "limit": 80}
  ]
}
```

Один запрос → один вызов выбранной модели через реестр Pi. Нет истории основной беседы, AGENTS, каталога навыков, дочернего shell, tool execution, записи исходников, автоматических повторов или fallback. Одновременно допускается один запрос. Неудачные отправленные попытки тоже расходуют счётчик. Для полного сброса лимита требуется новое явное разрешение человека.

Ответ ограничен findings/unknowns. Для каждого утверждения нужны точные путь, номера строк и цитата. Проверяются только переданные строки; полные SHA-256 исходников перепроверяются после вызова. Несовпадения, изменения файлов, tool calls, неправильный JSON и обрезанный ответ отвергаются.

**Проверенная цитата ≠ верное рассуждение.** Исходники и текст ответа остаются недоверенными данными. Модель может сделать неверный вывод из настоящей цитаты. Для редактирования/отладки перечитайте нужный актуальный диапазон обычным `read` и выполните проверки. Нет заявленного автоматического semantic verifier.

## 5. Лимиты

`.pi/context-tools.json` содержит только бюджет и режим guard; провайдера, ключей или `enabled` в нём нет.

| Параметр worker | По умолчанию |
|---|---:|
| `maxFiles` | 8 |
| `maxInputBytes` | 96 000 — сериализованный вопрос, пути, номера и текст |
| `maxFileBytes` | 2 MiB — локальное чтение каждого файла для snapshot/hash |
| `maxOutputTokens` | 1 500, дополнительно ограничено возможностями модели |
| `maxAnswerBytes` | 7 000 — проверенный JSON, без небольшой служебной обёртки |
| `timeoutMs` | 60 000 |
| `maxCallsPerSession` | 8 отправленных попыток |

Для каждого файла — один диапазон. Пустые выборки, binary и невалидный UTF-8 отвергаются. В запрос отправляется только выбранный диапазон, хотя для свежести локально хешируется весь файл до лимита. Перед отправкой есть консервативная проверка вместимости модели по байтам с резервом; это эвристика, не точный tokenizer.

Изменения JSON применяются после `/reload` и нового подтверждения. Уже подтверждённый бюджет фиксирован. Для изменения только guard в текущей сессии используйте команды.

## 6. Данные, отмена и стоимость

Локально создаются `.agent/tmp/context-tools/<run>/metrics.json` и, при успешной проверке, `answer.json`:

- metrics: выбранная модель, endpoint **origin без userinfo/query/path**, хеш вопроса, пути/диапазоны/хеши файлов, байты, длительность, outcome, полученный usage и оценка worker cost;
- answer: только проверенный JSON с цитатами, без сырого ответа модели;
- сырой корпус, полный вопрос, provider error bodies и ключи модуль намеренно не журналирует;
- сам провайдер получает одобренные исходники/вопрос по своим правилам хранения; это не локальная модель по умолчанию.

Запись начального receipt обязательна до отправки. Если финальная запись не удалась, это ошибка артефакта, а не успешное получение результата. При остановке процесса receipt может остаться `IN_FLIGHT`: считайте стоимость неизвестной.

Usage возвращается Pi как вложенный usage tool-result, **включая отвергнутые ответы, если провайдер успел сообщить usage**. Pi учитывает такой usage в сессионных итогах. Поэтому не складывайте `/session` total и worker receipt второй раз. Receipt содержит **только worker**, не стоимость основной модели.

`workerCostUsd` — каталоговая оценка Pi, **не инвойс**. Нулевые/отсутствующие тарифы дают `null`, а не «бесплатно». При timeout, Esc/abort, сетевой ошибке и незавершённой записи usage может отсутствовать. Тогда footer сам по себе не доказывает полноту счёта: сверяйте неизвестные worker attempts с провайдером. Отмена ограничивает ожидание и посылает abort, но не гарантирует нулевую оплату уже отправленного запроса.

Не отправляются известные credential/config пути, `.env*`, private-key файлы, `.pi`, `.git`, `.agent/tmp`, `.agent/handoffs`, node_modules, симлинки/junction и hardlinks. **Встроенные секреты в обычном `.ts`/`.json`/README надёжно не распознаются.** Отбор папок — ответственность человека. Gitignore/0600 не шифруют файлы; Windows ACL отдельно не настраиваются. Цитаты в `answer.json` тоже могут быть чувствительными.

Это не изоляция против вредоносных расширений, провайдерных адаптеров или процессов с теми же правами. Они могут изменять файлы/регистрации и использовать остальные возможности Pi. Используйте только проверенные расширения и ограничения ОС для недоверенного кода.

## 7. Сравнение и откат

Три варианта и валидатор учёта описаны в `EVALUATION.md`. Offline-тесты проверяют маршрутизацию и арифметику на синтетических данных, но не качество/цены реальных LLM. Заявлений «экономит 90%» здесь нет.

Повторный `context-tools` идемпотентен. При обновлении кода `--force` делает бэкап; существующий `.pi/context-tools.json` сохраняется **даже с `--force`**. Редактируйте бюджет вручную после просмотра схемы. Core-файлы и настройки не заменяются.

Для полного отката сначала `/context-tools disable` и остановка Pi, затем `restore` с manifest именно установки модуля (см. README). Изменённые после установки файлы автоматически не затираются. Перезапустите Pi. Бэкапы, логи и пустые папки намеренно остаются; содержимое исходников module не изменяет.

## Накладные расходы

После установки описание/schema инструмента добавляются к каталогу Pi даже при выключенном worker. Не путайте неизменный AGENTS-бюджет core с полным размером контекста с расширением. Для редких больших чтений targeted-read может оказаться выгоднее. Скрипт не повторяет запросы сам; поведение транспорта/кастомных provider adapters контролируется Pi и их настройками.
