# Руководство по репозиторию

[English](AGENTS.md)

## Структура проекта

- `scripts/agent-kit.mjs` — универсальный CLI, `scripts/lib/` планирует адаптеры; `kit.mjs` сохраняет установку Pi и откат.
- `portable/` содержит общие навыки и инструкции Pi, Codex, Claude Code и OpenCode.
- `project-template/` содержит помощники `.agent/`, шаблоны `.pi/` и ADR. Его `AGENTS.md` распространяется как шаблон; этот документ регулирует разработку комплекта.
- `global/` — общие навыки, настройки и фрагмент инструкций; `profiles/` — опциональные профили.
- `optional/context-tools/` — подключаемое расширение и логика оценки.
- `tests/` — тесты, `verification/` — свидетельства. Корневые Markdown описывают настройку и миграцию; `docs/languages.json` связывает переводы.

## Команды разработки и проверок

Нужен Node.js >=22.19.0; обязательных зависимостей и сборки нет. Из корня:

- `npm run check`: синтаксис JavaScript/TypeScript, JSON, метаданные навыков/шаблонов и бюджеты инструкций.
- `npm test`: полный набор встроенных тестов Node.js.
- `node --test tests/context-tools.test.mjs`: только тесты context-tools.
- `npm run setup -- --target "C:/work/sample-project" --agents all --dry-run`: просмотр установки вне комплекта.
- `npm run doctor -- --target "C:/work/sample-project"`: проверка адаптеров; прежняя диагностика Pi — `scripts/doctor.mjs`.
- `npm run context:summary -- path/to/evaluation.json`: проверка и сводка измерений.

## Стиль и именование

Используйте ES-модули `.mjs`, импорты `node:`, отступы два пробела, одинарные строки и точки с запятой. Идентификаторы — camelCase, имена файлов — описательный kebab-case. Общая логика — Node.js, shell-обёртки тонкие. UTF-8 без BOM, LF согласно `.gitattributes`. Отдельных форматтера и линтера нет.

## Тестирование

Используйте `node:test`, `node:assert/strict`, файлы `*.test.mjs` и названия по поведению. Создавайте временные фикстуры с очисткой, подменяйте вызовы провайдера. Покрывайте изменения, особенно пути, резервные копии, конфликты отката и согласие. Числового порога покрытия нет. Перед отправкой выполните обе проверки; CI охватывает Linux, Windows, macOS и Node 22.19.0/24. Указывайте пропуски; отделяйте офлайн-тесты от живых Pi/provider-проверок.

## Коммиты и pull request

Короткие повелительные заголовки: `Fix restore conflict detection`. PR объясняет проблему, поведение и проверку, ссылается на issues и обновляет документацию. Подготовка релиза и инвентаря — [CONTRIBUTING.ru.md](CONTRIBUTING.ru.md).

## Языки документации

Обновляйте обе версии вместе; runtime-переводы храните в `locales/ru/` вне поиска нативных ресурсов. Сохраняйте машинные идентификаторы. После ревью пары выполните `npm run docs:write` и `npm run docs:check`. Для настройки или обновления по просьбе пользователя следуйте `SETUP.ru.md` (английский: `SETUP.md`) и проверьте проект.

## Инварианты конфигурации

Сохраняйте офлайн-установку, совместимость Pi, явное подключение расширений и защиту отката. Сохраняйте настройки и инструкции пользователя. `npm run check` разделяет бюджеты Pi и переносимых инструкций. Навыки задают поведение; runtime-hooks дают только нативные адаптеры.
