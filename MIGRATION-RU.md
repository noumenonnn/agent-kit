# Переход v2 → v2.1

Распакуйте v2.1 отдельно. Для установки нового опционального модуля не нужно перезаписывать AGENTS, skills, CONTEXT, settings или ваши prompts:

```bash
node scripts/kit.mjs context-tools --target /path/to/project --dry-run
node scripts/kit.mjs context-tools --target /path/to/project
```

Команды работают на Node и Windows. Остановите активный Pi на время обновления файлов расширения, проверьте diff, затем перезапустите доверенный Pi. Если trust уже подтверждён и файлы не обновляются во время работы — `/reload` перечитает ресурсы. После загрузки: `/context-tools status`; отправка исходников разрешается отдельно через `/context-tools enable` и интерактивный выбор модели/папок.

Повторная установка сохраняет ваши файлы. Для обновления уже установленного кода модуля используйте `context-tools --force` после dry-run: будут бэкапы, core не меняется. Существующий `.pi/context-tools.json` сохраняется даже с force. При изменении его бюджета нужны `/reload` и новое подтверждение. Откат — manifest именно этой установки, по инструкции README.

Core v2 и прежние workflows остаются доступны без нового модуля. Не запускайте `init --force` только ради bulk-reader. Code-writer не входит в v2.1. Условия smoke-теста и ограничения — `CONTEXT-TOOLS-RU.md`.

# Миграция с исходного стартера (v1 → core v2)

Не выполняйте обновление поверх рабочих изменений вслепую. Остановите активные Pi-сессии, сохраните текущий diff/резервную копию и распакуйте v2.1 отдельно.

## 1. Глобальные файлы

```bash
node scripts/kit.mjs global --force --apply-settings --dry-run
```

`--force` обновляет шесть файлов навыков и управляемый блок глобального AGENTS с бэкапом. Дополнительные файлы внутри ваших навыков сохраняются. `--apply-settings` меняет только поля шаблона и глубоко сохраняет остальные, но это всё же изменение предпочтений — проверьте их. Без этого флага существующие settings не меняются, поэтому старое `compaction.enabled=false` само не исправится.

После просмотра плана примените ту же команду без `--dry-run`. Если нужен agenticoding, следуйте явному подключению и smoke-тестам из README, затем примените его профиль; не отключайте compaction по привычке.

## 2. Проект

```bash
node scripts/kit.mjs init --target /path/to/repo --force --dry-run
```

Если вы редактировали проектный `AGENTS.md`, `CONTEXT.md`, conventions, ADR или шаблоны, лучше перенесите изменения вручную: `--force` заменяет файлы комплекта целиком, хотя и сохраняет оригиналы. **Без `--force` существующие старые скрипты/шаблоны остаются старыми.**

Проверьте diff, примените нужный вариант и выполните project doctor. Правила временных файлов добавляются в настоящую `.gitignore`. Если логи раньше были закоммичены, ignore их не удалит из истории/индекса; отдельно рассмотрите удаление отслеживания и ротацию уже раскрытых секретов.

## 3. Изменения поведения

- core теперь не требует расширения и сохраняет auto-compaction;
- мелкие задачи используют `/efficient-task`, а не обязательные четыре фазы;
- `/skill:tdd`, `/skill:code-review` — правильные имена навыков Pi;
- verify больше не объявлен read-only: тестам/сборке разрешены артефакты, но не autofix/snapshot updates;
- stdout ограничен байтами, логи пишутся потоково, у команд есть timeout;
- Windows: неявный shell убран; для npm/pnpm `.cmd` требуется явная оболочка;
- временный handoff по умолчанию перенесён в `.agent/handoffs/`;
- Matt устанавливается из проверенного локального commit, без floating `npx skills@latest`;
- автоматического доказательства безопасности, экономии или совместимости всех моделей нет.

## 4. Проверка после обновления

В распакованном комплекте: `node scripts/check-kit.mjs`, `node --test`.
В своём проекте: doctor, `/reload` после разрешённой перезагрузки ресурсов, маленькая задача с известным тестом. Отдельно проверьте модельные роли, readonly→build→verify переход и handoff, если используете расширение.

При проблемах используйте backup manifest и `restore` из README. Он не перезапишет более поздние пользовательские изменения; такие конфликты нужно разобрать вручную.
