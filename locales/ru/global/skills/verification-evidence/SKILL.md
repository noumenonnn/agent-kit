# Свидетельства проверки

Начните с целевых проверок поведения, затем выполните соразмерные общие, статические проверки и сборку. Проверяйте фактическое обнаружение тестов и утверждений: код 0, успешная сборка или отсутствие замечаний сами по себе не доказывают корректность.

Для ошибки со стабильной точкой проверки добавьте регрессионный тест, воспроизводящий ошибку до исправления и проходящий после. Используйте существующий TDD-процесс вместо его дублирования.

Тесты могут записывать кэши и артефакты: не обещайте режим только чтения на уровне ОС. Не применяйте автоисправления, обновления снимков или зависимостей только ради зелёного результата. Если среда не позволяет проверку, сообщите о блокировке. Не запускайте её одновременно с изменением тех же файлов.

В итоговом отчёте укажите выполненные команды, область, результаты и пути к свидетельствам; для ошибок — наблюдение и контекст; для заблокированных и невыполненных проверок — причину; для рисков — практическое значение.

`PASS` допустим только для реально выполненных релевантных проверок. Результаты до последней правки не считаются актуальными без оценки её влияния.
