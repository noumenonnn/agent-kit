# Универсальная оснастка: исследование интеграций

Проверено 8 сентября 2026 года по первичным источникам. Это обоснование архитектуры, а не утверждение, что все описанные возможности уже реализованы или проверены в живых клиентах. Реализованная матрица приведена в [UNIVERSAL-RU.md](UNIVERSAL-RU.md).

## Что перенять у Portal и аналогов

**Spotify Portal AI Plugins** объединяет общие skills с отдельными манифестами Claude Code, Codex и Cursor. Основной продукт обслуживает каталог Spotify через Portal CLI: setup, doctor, поиск, сведения о сервисах, действия. Это хороший образец предсказуемого пути «настроить → проверить → использовать», но обязательная зависимость от Portal для данного проекта не нужна. [Репозиторий Portal](https://github.com/spotify/portal-ai-plugins).

**Shunt** — отдельный плагин для Claude Code. Hooks ограничивают большие чтения, scripts вызывают AiKA, skills объясняют выбор инструмента. Полезны именованные аргументы, отдельный вызов worker, точечное чтение при редактировании и отдельные транспортные проверки. Его порог 350 строк и результаты 82–94% получены в конкретных сценариях; это не универсальная оценка экономии. Делегирование требует Portal/AiKA и не заменяет чтение точного кода при отладке. [Shunt README](https://github.com/spotify/portal-ai-plugins/blob/main/plugins/shunt/README.md).

**Vercel Skills** показывает удобные операции установки из локальной папки или Git, выбор агентов, project/global scope, list/update/remove и копирование как альтернативу symlink. Для Windows и текущих правил безопасной установки разумно использовать обычные файлы с учетом установленных версий. Устанавливать этот CLI как обязательную зависимость не требуется. [Vercel Skills](https://github.com/vercel-labs/skills).

**Anthropic Skills** демонстрирует упаковку самостоятельных навыков и групп навыков в marketplace. В качестве общего формата подходят `SKILL.md` с `name` и конкретным `description`, локальные scripts и references. [Anthropic Skills](https://github.com/anthropics/skills).

## Подтвержденные контракты клиентов

| Клиент | Переносимый слой | Нативный слой |
| --- | --- | --- |
| Pi | `.pi/skills/` и `.agents/skills/`; явный вызов `/skill:name` | `package.json` с `pi.skills`, `pi.prompts`, `pi.extensions`; `.pi/extensions/*/index.ts` |
| Codex | `.agents/skills/<name>/SKILL.md`; явный вызов `$name` | `AGENTS.md` с приоритетом непустого `AGENTS.override.md`; plugins — отдельный способ распространения |
| Claude Code | `.claude/skills/<name>/SKILL.md`; команда `/name` | `.claude-plugin/plugin.json`, `skills/`, `hooks/hooks.json`; команда `/plugin:name` |
| OpenCode | `.opencode/skills/`, `.agents/skills/`, `.claude/skills/` | `.opencode/plugins/*.js` или `.ts`; npm-пакеты через `plugin` в конфигурации |

Pi загружает проектные навыки после доверия проекту. Пакет можно подключить локальным путем через `pi install /absolute/path/to/package -l`; пути ресурсов в манифесте считаются от корня пакета. Локальное подключение не копирует пакет: исходная папка должна оставаться доступной. Устанавливать extension необязательно для использования skills и prompts. [Pi skills](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md), [Pi packages](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md).

Pi extension получает `ExtensionAPI`; `tool_call` позволяет блокировать вызов, `tool_result` — менять результат, `session_before_compact` — настраивать сжатие. Есть нативные команды, UI, сохранение состояния и `/reload`. Полную поддержку Pi следует сохранять отдельным адаптером, не ограничивая ее общим форматом skills. [Pi extensions](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md).

Claude Code поддерживает локальную пробу `claude --plugin-dir ./plugin`. Компоненты находятся рядом с `.claude-plugin/`, а не внутри нее. `PreToolUse` получает JSON через stdin; отказ возвращается через `hookSpecificOutput.permissionDecision: "deny"`. Отсутствие решения сохраняет обычную проверку разрешений. Установка skills сама по себе не устанавливает hooks. [Claude plugins](https://code.claude.com/docs/en/plugins), [Claude skills](https://code.claude.com/docs/en/skills), [Claude hooks](https://code.claude.com/docs/en/hooks).

OpenCode автоматически загружает локальные JS/TS plugins при запуске. Модуль экспортирует функцию, возвращающую handlers, например `tool.execute.before`. Hook `experimental.session.compacting` существует, но его экспериментальный статус требует отдельного контроля совместимости. OpenCode читает корневой `AGENTS.md`; `CLAUDE.md` служит fallback. Нужно избегать одинаковых skills в нескольких обнаруживаемых каталогах. [OpenCode plugins](https://opencode.ai/docs/plugins/), [OpenCode skills](https://opencode.ai/docs/skills/), [OpenCode rules](https://opencode.ai/docs/rules/).

## Предлагаемая архитектура и UX

Codex обнаруживает skills в `.agents/skills` от рабочего каталога до корня репозитория. При настройке проекта используем этот формат без изменения пользовательского `config.toml`. [OpenAI: Build skills](https://learn.chatgpt.com/docs/build-skills). Для инструкций в каждом каталоге выбирается один файл: `AGENTS.override.md`, затем `AGENTS.md`; это требует учитывать существующий override при добавлении управляемого блока. [OpenAI: AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Уточнение по OpenCode v1.18.10: skills хранятся по имени, последующая запись заменяет предыдущую с предупреждением; загрузка параллельная, фиксированный приоритет `.agents` над `.claude` не гарантируется. Идентичные копии допустимы по содержимому, расхождения требуют диагностики. [Присваивание skill](https://github.com/anomalyco/opencode/blob/v1.18.10/packages/opencode/src/skill/index.ts#L115-L129), [параллельная загрузка](https://github.com/anomalyco/opencode/blob/v1.18.10/packages/opencode/src/skill/index.ts#L223-L226).

Следующие решения — вывод для этого репозитория:

1. **Общее офлайн-ядро:** небольшой постоянный policy, навыки по требованию, переносимые Node.js helpers и проектные references. Отдельные адаптеры создают именно файлы нужного клиента. Один исходник каждого навыка; копии и их версии учитываются установщиком.
2. **Одна точка входа:** setup для нового или существующего каталога с выбором клиентов; preview показывает создаваемые, сохраненные и конфликтующие файлы. Повторный запуск идемпотентен. После применения — status/doctor и точная команда первого действия.
3. **Честная матрица возможностей:** отдельно показывать skills, команды, runtime guard и worker. Не обозначать обычную подсказку как гарантированный перехват инструментов. Pi остается полноценным обязательным адаптером.
4. **Без скрытой настройки:** сохранять пользовательские инструкции и настройки, обновлять только управляемые части, обеспечивать backup/restore. Не устанавливать провайдеры, не менять модель и не запускать агента во время подготовки проекта.
5. **Расширения по выбору:** переносимые workflows работают сразу после подготовки; нативный guard и вызовы worker включаются явно. Отказ должен объяснять объем чтения и давать пригодный следующий шаг: диапазон, поиск или разовое разрешение.

## Оптимизация контекста

Agent Skills стандартизует progressive disclosure: сначала метаданные навыков, затем нужная инструкция, затем отдельные ресурсы. Уместен небольшой каталог конкретных навыков; переносить все справочники в постоянный `AGENTS.md` не следует. [Agent Skills](https://agentskills.io/home), [Спецификация](https://agentskills.io/specification).

Практики context engineering включают получение исходников по мере необходимости, небольшие однозначные инструменты, структурированные заметки и сжатие долгих сессий. Контекст должен быть достаточным для задачи, а не просто минимальным по объему. [Anthropic: effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents).

Для этого проекта целесообразно: поиск → диапазон строк → полный файл при обоснованной необходимости; ограниченный вывод с указанием усечения; полные логи в локальном артефакте; краткий handoff с решениями, проверками и следующими шагами; ссылки на путь/строки и отпечаток исходника для проверки свежести worker-ответа. Сводка не является доказательством корректности кода. Считать общие затраты principal + worker, latency и качество выполнения, различать неизвестную стоимость и ноль. Эти меры требуют собственных сравнительных запусков; обещать процент экономии до измерения нельзя.

## Границы доказательств

Изучены документация и исходные схемы интеграций; сторонний код не копировался. Документация main может изменяться, поэтому выпуск должен фиксировать реально проверенные версии клиентов. Офлайн-тесты установщика и fixtures подтверждают файловые контракты, но живые smoke tests отдельно должны проверить обнаружение навыков, пользовательский первый запуск, нативные hooks, Pi UI и работу провайдера. Отсутствующий клиент или авторизация отражаются как «не проверено», а не как успешная полная совместимость.
